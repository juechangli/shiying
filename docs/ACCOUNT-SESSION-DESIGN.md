# 通用账号与会话设计

状态：设计提案，尚未实现。适用于普通、获授权内容的站点授权；不包含特定受限内容的下载适配。

基线：VideoDock 1.0.1。该版本只支持公开访问下载；本设计不改变已发布安装包的行为。

## 1. 用户可见行为

默认不保存登录。用户在任务中主动点击“连接账号”，由网站自己的授权页面完成登录，拾影只展示授权状态，不显示密码、Cookie 或令牌。

任务遇到明确的登录要求时进入“等待登录”，而不是长时间显示 0%。提示文案为：“该网站要求登录。连接账号后将重新检查这个任务的访问权限。”按钮为“连接账号”和“取消任务”。

授权面板显示网站名称、请求权限和保存方式：

- “仅本次使用”：默认选中；退出拾影后不会恢复登录。
- “在此电脑记住登录”：默认关闭；用户主动启用后才持久化必要授权。
- “取消”：关闭授权界面，任务继续保持暂停，不启动下载。

授权成功后先重新检查权限，只恢复该次授权请求关联的任务。登录成功不等于获得下载权限。没有可用授权下载方式的网站应明确显示“不支持该网站的授权下载”。

账号页显示网站、脱敏账号标识、临时/已保存、有效/过期/需重新授权。提供“重新登录”“改为仅本次使用”和“断开并清除”。不要提供显示或复制原始凭证的入口。

## 2. 错误分类

| 内部结果 | 所需证据 | 用户提示与处理 |
| --- | --- | --- |
| AUTH_REQUIRED | 网站明确的认证错误或经过验证的站点响应 | 等待登录，显示连接按钮 |
| AUTH_EXPIRED | 已授权会话被网站明确判为失效 | 暂停关联任务，提示重新登录 |
| ACCESS_DENIED | 网站明确拒绝当前账号权限 | 停止重试，说明登录未解决权限问题 |
| MEDIA_UNAVAILABLE | 删除、不可用或媒体信息为空 | 提示未取得媒体信息，不自动归因为需要登录 |
| PROVIDER_UNSUPPORTED | 没有经过验证的授权接入方式 | 说明尚不支持，不展示假登录流程 |
| NETWORK_ERROR | DNS、TLS、超时、连接中断 | 保留具体网络原因，允许用户重试 |

空媒体响应、403 或“没有视频”不能单独证明需要登录；站点适配层必须给出可测试的分类规则。没有可靠证据时保留未知状态。

## 3. 职责与边界

| 组件 | 职责 | 可持有的数据 |
| --- | --- | --- |
| 账号界面 | 用户授权、保存偏好、展示状态 | 脱敏描述和不透明账号 ID |
| SessionManager（主进程） | 会话生命周期、隔离和撤销 | 当前进程所需授权材料 |
| CredentialStore（主进程） | 可选加密持久化、删除和迁移 | 加密授权记录；密钥由系统保护 |
| ProviderAdapter | 网站明确支持的授权、状态确认和权限检查 | 仅属于该网站且在有效期内的授权 |
| 下载任务管理器 | 等待/恢复/取消任务 | accountId、授权版本号、状态；不存原始凭证 |

首选网站支持的官方授权机制。每个站点单独登记允许访问的授权入口、回调地址、权限范围和媒体域名。不要默认扫描或导入 Edge、Chrome 等浏览器的全部登录数据。

授权窗口与普通应用界面隔离；网页不能调用文件管理或原生应用 IPC。新窗口、回调和重定向按已审核的站点规则处理。需要用户输入密码、验证码或完成站点确认时，由用户自己操作。

## 4. 临时会话

- 授权窗口、Cookie、站点存储及缓存均使用独立的非持久化会话；不能仅把一个 JavaScript 变量放入内存，却沿用持久化浏览器配置。
- 按网站与账号隔离，不复用桌面服务登录或手机配对会话。
- 不把凭证放入历史 JSON、日志、错误报告、命令行参数或下载 URL；默认路径不得依赖明文 Cookie 临时文件。
- 下载器若只能通过磁盘明文文件接收凭证，不满足“默认不落盘”的验收要求；应明确标为未支持，或另行设计受控传递方式并审核。
- 退出时先停止新请求，取消使用临时会话的任务与后台进程，再关闭授权窗口、网络连接及会话，清除引用。
- “退出即释放”指不主动持久化、退出后不恢复会话，不承诺操作系统交换区、崩溃转储或 JavaScript 内存中所有副本的物理擦除。

## 5. 用户可选的长期保存

只保存继续授权所需的最少信息，不保存密码。保存由账号页的明确操作触发，不能根据“登录成功”自动开启。

候选方案是系统凭证存储或 Electron safeStorage 保护的加密文件。实现前应核对所用 Electron 版本的 API 和平台行为，并在目标系统实测。加密能力不可用或只能降级为弱保护时，关闭“记住登录”，仍允许临时会话，不回退到明文。

保存记录包含格式版本、站点标识、脱敏账号 ID、有效期和密文。加密密钥不写入仓库或同目录配置。磁盘写入采用原子替换，文件权限限于当前用户。解密失败时要求重新授权，禁止将敏感字段写入日志。

将“已保存”改为“仅本次使用”时，先删除持久化副本，当前内存会话可继续使用至退出。取消删除或系统存储拒绝操作时，不得假报清除成功。

macOS 的不同应用构建签名可能影响凭证存储识别；当前 1.0.1 没有稳定发布签名，长期保存与升级迁移必须在后续版本单独验收。系统加密不能保证阻止同一用户权限下的所有恶意程序。

## 6. 状态与任务关联

账号状态：未连接 → 正在授权 → 有效 → 过期/需重新授权 → 正在清除 → 未连接。用户取消授权返回未连接；任务保留等待状态，直到用户重试或取消。

每次授权或断开操作增加会话版本号。任务只引用明确的 accountId 与版本号；旧回调、旧任务不能在用户退出后重新启用授权。相同网站的多个等待任务共用一次授权提示，不重复弹窗。

用户退出账号时取消使用该账号的进行中任务，撤销内存能力并尝试删除保存记录。远端授权撤销若网站提供官方接口则调用；不支持时明确区分“本机已清除”和“远端已撤销”。

检测到认证失效最多触发一次重新授权提示，避免无限重试、重复创建任务或静默换用另一个账号。

## 7. 手机端

手机配对不等于获得桌面网站账号权限。默认手机任务不能使用桌面保存的第三方账号；如未来增加委托，必须由电脑用户对具体网站与手机会话单独授权。

手机 API 只返回脱敏状态，不能列出账号凭证、导出 Cookie、修改保存方式或触发后台凭证读取。关闭手机连接撤销对应委托，不影响电脑用户对自己的账号管理。

## 8. 最小实现顺序

1. 增加错误分类与“等待登录”任务状态，用模拟适配器验证界面，不宣称已支持真实站点。
2. 实现只在内存中运行的 SessionManager 和一个具备官方授权方式的非成人测试站点适配器。
3. 验证“授权 → 权限检查 → 恢复原任务 → 退出清理”完整流程。
4. 添加显式可选的加密持久化、清除与升级迁移。
5. 在 Mac 和 Windows 上完成实际授权与崩溃恢复测试后，才发布支持账号功能的新版本。

## 9. 验收标准

- 未登录、过期、无权限、网络错误、空媒体响应各有独立的自动测试，不误判为同一原因。
- 临时模式经过正常退出、强制退出、崩溃和重启后不会恢复登录；检查应用数据目录、缓存与任务历史没有明文授权材料。
- 日志、IPC 返回、手机 API、进程命令行、错误提示均不出现凭证。
- 保存关闭时没有持久化记录；加密不可用时明确拒绝保存；清除后重启不能恢复账号。
- 拒绝跨站发送凭证、未登记的回调、陈旧授权回调和未经电脑用户允许的手机账号访问。
- 授权取消和网络失败不自动重开授权窗口；多任务只恢复用户授权范围内的任务。
- 长期保存跨应用升级、系统存储锁定、密码变更和账号撤销均有人工验证记录。
